# Contributing to Carbure

Thank you for your interest! Questions and ideas go to the
[Discord server](https://discord.gg/QsxYw4Rx9D); bugs and feature requests to
the [issues](https://github.com/ltoinel/Carbure/issues/new/choose); vulnerabilities are
reported privately (see [SECURITY.md](SECURITY.md)).

## Workflow

1. **Issue first**: every change is tracked by an issue.
2. **Branch** from `main`, named `<type>/<issue>-<short-topic>`:
   `feat/31-scam-blacklist`, `fix/26-codeql-alerts`, `docs/25-security-policy`.
3. **Pull request** to `main`, with `Closes #<issue>` in its description. `main` is
   protected: no direct push.
4. The PR is **squash-merged**: its title becomes the only commit on `main`.

## PR titles (and commit messages)

[Conventional Commits](https://www.conventionalcommits.org/), checked by the CI:

```text
type(scope): description
```

English, imperative mood, lowercase start, no final period.

| Type | For | Example |
|---|---|---|
| `feat` | A new feature | `feat(sync): approve the bank 2FA from the portal` |
| `fix` | A bug fix | `fix(docker): keep the published port in redirects` |
| `security` | A vulnerability fix or hardening | `security(oauth): keep the request out of sessionStorage` |
| `perf` | A performance improvement | `perf(api): cache the routes in APCu` |
| `refactor` | Code change without behavior change | `refactor(portal): split the sync module` |
| `docs` | Documentation only | `docs: add a security policy` |
| `test` | Tests only | `test(e2e): escape the labels in regexes` |
| `ci` | GitHub workflows | `ci: test PHP 8.5` |
| `chore` | Tooling, repository, dependencies | `chore(deps): bump mariadb from 11 to 13` |

The scope is optional: `api`, `portal`, `sync`, `import`, `mcp`, `oauth`, `docker`, `db`,
`deps`… A breaking change is marked with `!` (`feat(api)!: …`) and stays exceptional: the
iOS app is not updated at the same time as the server, so the API must remain backward
compatible.

Inside a branch, use the same format; the body of a commit lists the changes:

```text
fix(sync): relay the bank messages during the 2FA

- Woob: give the non-JSON lines of the output to a callback
- Bank: send them as "Bank message <account>: ..."
```

## Labels and release notes

Label each PR with its kind: `enhancement`, `bug`, `security`, `documentation` or
`dependencies`. The release notes generated by GitHub are grouped by these labels
(`.github/release.yml`).

## Code

The rules of the code (architecture, conventions, tests, definition of done) are in
[AGENTS.md](AGENTS.md), for humans and coding agents alike. Before opening a PR:

```bash
composer install                             # development tools (PHPStan, PHPUnit)
git config core.hooksPath .githooks          # lint + types on commit, unit tests on push
composer phpstan                             # types of the PHP code
composer test                                # PHP unit tests
node --test 'tests/portal/*.test.mjs'
```

A change of the portal comes with its Playwright test (`tests/e2e/specs/`); a change of the
schema with a migration in `sql/migrations/` (see [docs/developpement.md](docs/developpement.md)).
